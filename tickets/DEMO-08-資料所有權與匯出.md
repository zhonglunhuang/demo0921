## 目的（要解決什麼問題）

做到 300 戶後被系統綁住，轉換成本會非常高。本票用一個明確的頁面讓客戶看到：所有資料隨時可完整匯出、
有 API、資料屬於客戶公司——這是提案時的信任承諾，不只是功能（對應需求 #20）。

> **共同背景（8 張票共用）**：本專案是「提案網站」，不是真正的營運系統。系統虛構品名「租務中樞」，
> 客戶化名「安居包租代管」。全站純靜態 HTML/CSS/JS、Apple 網站風格（白底為主、黑底區塊穿插、大字標題、
> 毛玻璃導覽列、滾動淡入）、繁體中文、手機可看。所有資料為假資料（同一批 103 間物件，桃園中壢為主），
> 定義在共用資料檔，各功能畫面互相一致。每個功能都要同時出現在兩條路徑：
> (A) **進系統操作**——可點、可切換、有假資料在跑的畫面；
> (B) **功能導覽**——一條步驟流程，畫面在頁上逐步動起來（可自動播放、可手動上下一步），旁邊有白話說明。

## 使用角色與情境

- 客戶以老闆視角看匯出中心與資料所有權聲明。
- 功能導覽展示一條流程。

## 需求細節

### #20 資料匯出、API 與所有權
- 匯出中心：可勾選租客、租約、帳款、修繕、事件、照片，選格式（CSV / JSON / 完整備份 ZIP），按「匯出」→
  進度條 → 「匯出完成」與檔案清單（模擬，不真的下載）。
- 匯出歷史：每次匯出的時間、內容、執行者。
- API 說明頁：以清單列出主要資料的讀取端點（例：物件、租約、帳款、工單），附一段範例回應（假資料），
  說明「換系統商也能把資料全部帶走」。
- 資料所有權聲明區塊（Apple 式黑底大字）：三句承諾——資料屬於安居包租代管、隨時可完整匯出、不因換系統商而受綁。

### 功能導覽（一條流程）
1. 勾選全部資料 → 選完整備份 → 匯出 → 進度條 → 完成 → 看 API 範例 → 所有權聲明。
