## 目的（要解決什麼問題）

超過 100 間之後，設備、修繕、水電、鑰匙靠人記一定亂。本票展示系統如何記住每台設備的一生、
把修繕變成有廠商、有報價、有成本控制的流程，並從用量與鑰匙數量自動抓異常（對應需求 #6、#7、#8、#9）。

> **共同背景（8 張票共用）**：本專案是「提案網站」，不是真正的營運系統。系統虛構品名「租務中樞」，
> 客戶化名「安居包租代管」。全站純靜態 HTML/CSS/JS、Apple 網站風格（白底為主、黑底區塊穿插、大字標題、
> 毛玻璃導覽列、滾動淡入）、繁體中文、手機可看。所有資料為假資料（同一批 103 間物件，桃園中壢為主），
> 定義在共用資料檔，各功能畫面互相一致。每個功能都要同時出現在兩條路徑：
> (A) **進系統操作**——可點、可切換、有假資料在跑的畫面；
> (B) **功能導覽**——一條步驟流程，畫面在頁上逐步動起來（可自動播放、可手動上下一步），旁邊有白話說明。

## 使用角色與情境

- 客戶以「修繕人員 / 租務管理員」視角操作；老闆視角看成本異常。
- 功能導覽展示四條流程。

## 需求細節

### #6 房間設備履歷
- 每間房設備清單：冷氣、冰箱、洗衣機、熱水器、電視、床墊等；每台有品牌、型號、購入日期、保固到期、
  維修紀錄（日期、內容、金額、廠商）、累計維修費。
- 保固到期 30 天內標示；**AI 汰換建議**：假資料至少 1 台冷氣「5 年內修 4 次、累計 13,000 元」，系統顯示
  「建議汰換而非再修」並可一鍵建立採購待辦。

### #7 廠商資料庫＋報價＋成本控制
- 廠商列表：分類（水電、冷氣、鎖匠、清潔、油漆…）、服務區域、電話、過去報價、平均完工天數、返修率、評分。
- 工單流程：報修（含照片、AI 初步排查文字）→ 派工（選廠商）→ 上傳報價 → 核准金額（老闆 / 管理員）→
  完工照片 → 發票 → 付款狀態；每一步在工單時間軸留紀錄。
- **價格異常警示**：假資料至少 1 筆「同項目（換馬桶水箱零件）A 廠商平均 1,800，本次報 3,500」，
  核准畫面顯示異常提示與歷史平均。

### #8 水電異常偵測
- 每房水、電用量趨勢圖（近 12 個月）＋基準線（過往平均）。
- 異常規則：用量超過基準 2 倍 → 警示「疑似漏水」；空房卻持續用電 → 警示；假資料至少 1 間水表 8 度→25 度、
  1 間空房持續用電。
- 異常列表可一鍵建立工單（連到 #7）。

### #9 鑰匙、門禁卡、磁扣、遙控器管理
- 每戶：鑰匙、磁扣、車庫遙控器、信箱鑰匙的總數、租客領用數、歸還數；領用 / 歸還有日期與簽收紀錄。
- 退租點交時短少 → 自動加入退租扣款（連到 DEMO-02 押金結算）。
- 智慧鎖示意區塊：「入住自動產生密碼、退租自動失效」的流程圖（示意，不串真實硬體）。

### 功能導覽（四條流程）
1. 冷氣又壞 → 查履歷 → 看到修過 4 次 → AI 建議汰換 → 建立採購待辦。
2. 租客報修 → 派工 → 廠商報價 3,500 → 系統警示異常（平均 1,800）→ 改派另一家 → 完工 → 付款。
3. 水表用量從 8 度跳到 25 度 → 系統警示疑似漏水 → 一鍵派工檢查。
4. 退租點交鑰匙少一把 → 自動列入押金扣款 → 智慧鎖密碼失效。

## 驗收標準

- [x] 設備履歷至少 1 台冷氣顯示「修 4 次、累計 13,000、建議汰換」並可建立採購待辦
- [x] 廠商列表有分類 / 區域 / 報價 / 完工速度 / 返修率；工單可從報修一路走到付款，每步有時間軸紀錄
- [x] 至少 1 筆報價顯示價格異常警示與歷史平均
- [x] 水電趨勢圖有基準線，至少 1 間疑似漏水、1 間空房用電異常，可一鍵建立工單
- [x] 鑰匙管理有領用 / 歸還紀錄，短少會出現在押金扣款
- [x] 四條功能導覽可自動播放與手動切步；iPhone 可讀；`make check` 綠燈

## 邊界（明確不做什麼）

- 不串真實智慧鎖、水電表或廠商系統。
- 不做採購 / 庫存管理（倉庫庫存與設備履歷不同，明確不做）。
