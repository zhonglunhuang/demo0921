## 目的（要解決什麼問題）

員工每天打開系統不該看到 100 戶，而是只看到「今天要人工處理的 7 件」。本票展示 AI 工作中心首頁、
與一般修繕分開的重大事件管理、角色權限與金額改動的操作紀錄，以及每件事都有負責人與期限的待辦與績效
（對應需求 #12、#14、#15、#18）。

> **共同背景（8 張票共用）**：本專案是「提案網站」，不是真正的營運系統。系統虛構品名「租務中樞」，
> 客戶化名「安居包租代管」。全站純靜態 HTML/CSS/JS、Apple 網站風格（白底為主、黑底區塊穿插、大字標題、
> 毛玻璃導覽列、滾動淡入）、繁體中文、手機可看。所有資料為假資料（同一批 103 間物件，桃園中壢為主），
> 定義在共用資料檔，各功能畫面互相一致。每個功能都要同時出現在兩條路徑：
> (A) **進系統操作**——可點、可切換、有假資料在跑的畫面；
> (B) **功能導覽**——一條步驟流程，畫面在頁上逐步動起來（可自動播放、可手動上下一步），旁邊有白話說明。

## 使用角色與情境

- 客戶切換老闆 / 租務管理員 / 會計 / 修繕人員視角，看到的資料與畫面不同。
- 功能導覽展示四條流程。

## 需求細節

### #15 AI 工作中心（進系統後的首頁）
- 首屏一句話：「今天需要人工處理 **7** 件」，下方 7 張卡：帳款金額不符 1、欠租 2、AI 無法判斷修繕 1、
  屋主合約即將到期 1、退租押金尚未結算 1、空房超過 14 天 1；每張卡點進去到對應功能畫面。
- 其餘 96 間顯示為一行「96 間一切正常」，可展開看清單但預設收合。
- 角色切換後卡片內容不同（會計只看到帳款相關、修繕人員只看到修繕相關）。

### #12 重大事件／客訴案件管理
- 與修繕工單分開的「事件」模組：事件等級（一般 / 重大 / 緊急）、類型（漏水至樓下、鄰居噪音、警察到場、
  租客失聯、寵物違規、吸菸、非法使用、公安事件）、照片、對話紀錄、處理人員、完整時間軸。
- 假資料至少 1 件「漏水至樓下」緊急事件，時間軸從通報到結案有 6 步以上。
- 事件可指派負責人、加註、升級等級。

### #14 權限＋操作紀錄（Audit Log）
- 權限矩陣頁：角色（老闆 / 會計 / 租務管理員 / 修繕人員 / 倉管）× 資料類型（身分證、銀行帳戶、租金、押金、
  聯絡電話、修繕成本…）的可見 / 可改標示。
- 切換角色時，租客詳情頁上的身分證、銀行帳戶等欄位會依權限**打碼或隱藏**。
- 操作紀錄列表：「2026-09-20 14:36 劉○○ 將 A01 租金由 13,000 改為 12,000」；可依人、依物件、依資料類型篩選；
  任何金額改動都要能在此查到。示範：在畫面上改一次租金 → 紀錄立即多一筆。

### #18 待辦與員工績效追蹤
- 每件待辦有負責人與期限；管理員視圖：「目前 20 件待辦、逾期 3 件」，逾期紅標。
- 本月完成統計：入住、退租、報修、催租、帶看各幾件；以長條圖呈現各員工完成數（強調避免事情只留在 LINE 群、不是盯人）。

### 功能導覽（四條流程）
1. 管理員早上打開首頁 → 只看到 7 件 → 逐件點開處理 → 數字降到 0 → 「今天沒有需要你處理的事」。
2. 樓下住戶通報漏水 → 建立緊急事件 → 派人 → 照片與對話 → 升級 → 結案，時間軸完整。
3. 會計登入看不到身分證 → 切換老闆 → 改 A01 租金 → 操作紀錄立即出現一筆。
4. 管理員待辦逾期 3 件 → 系統提醒 → 指派 → 本月績效統計更新。

## 驗收標準

- [ ] 事件模組有等級 / 類型 / 照片 / 對話 / 處理人 / 時間軸，至少 1 件緊急漏水事件 6 步以上

- [ ] 待辦有負責人與期限、逾期紅標；本月完成統計圖可看
- [ ] 四條功能導覽可自動播放與手動切步；iPhone 可讀；`make check` 綠燈

## 邊界（明確不做什麼）

- 不做真實登入與帳號系統（角色切換為示範用下拉選單）。
- 不做績效考核規則、獎金計算。
