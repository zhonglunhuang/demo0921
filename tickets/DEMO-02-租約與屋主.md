## 目的（要解決什麼問題）

包租代管業者有兩份租約：屋主→公司（上游）、公司→租客（下游）。現有工具通常只管下游，導致
「上游先到期、租客還在住」的風險沒人看見、押金幾年後變成帳務爭議、文件每次都重打。本票展示這三件事
在「租務中樞」裡怎麼被系統化管理（對應需求 #1、#4、#17）。

> **共同背景（8 張票共用）**：本專案是「提案網站」，不是真正的營運系統。系統虛構品名「租務中樞」，
> 客戶化名「安居包租代管」。全站純靜態 HTML/CSS/JS、Apple 網站風格（白底為主、黑底區塊穿插、大字標題、
> 毛玻璃導覽列、滾動淡入）、繁體中文、手機可看。所有資料為假資料（同一批 103 間物件，桃園中壢為主），
> 定義在共用資料檔，各功能畫面互相一致。每個功能都要同時出現在兩條路徑：
> (A) **進系統操作**——可點、可切換、有假資料在跑的畫面；
> (B) **功能導覽**——一條步驟流程，畫面在頁上逐步動起來（可自動播放、可手動上下一步），旁邊有白話說明。

## 使用角色與情境

- 客戶（老闆 / 租務管理員視角）在電腦上操作假資料，看上游租約、押金、文件如何運作。
- 客戶在功能導覽中看三條流程的動態演示。

## 需求細節

### #1 上游房東／包租契約管理
- 上游租約列表：屋主姓名、物件編號、租期起迄、每月付屋主租金、押金、付款日、調租條件、修繕責任歸屬、
  房屋稅 / 管理費 / 水電由誰負擔、提前解約條款、續租通知日；可搜尋、可篩「有風險」「30 天內到期」。
- 物件詳情頁：上游與下游兩份租約**並列時間軸**，一眼看出誰先到期。
- **風險警示**：上游到期日早於下游到期日 → 該物件顯示紅色警示「上游租約 2026-11-30 到期，房客租約到
  2027-03-31，仍有房客在租」；列表頂端有警示計數；至少 3 間命中。
- 到期 60 天前自動產生「續租通知」待辦（顯示在待辦與 AI 工作中心）。

### #4 押金管理（獨立模組）
- 每戶押金卡：收到金額、收到日期、預計退還金額、扣除項目（修繕 / 清潔 / 欠租 / 鑰匙遺失，各含金額與依據）、
  退款日期、退款證明（假圖縮圖）、狀態（持有中 / 結算中 / 已退還 / **逾期未結算**）。
- 押金總覽：持有總額、本月待結算、逾期未結算清單；逾期者顯示提醒。
- 結算流程：點「開始結算」→ 系統帶入退租整備的扣款項 → 確認 → 產生押金結算單（接 #17）。

### #17 自動產生文件
- 文件中心：8 種文件——租賃契約、續約書、租金調整通知、催繳通知、退租確認書、點交表、押金結算單、修繕確認書。
- 選文件類型 → 選租客 / 物件 → 產生預覽：姓名、地址、租金、租期、押金等欄位自動帶入，不需再手打。
- 預覽頁有「下載 PDF」「以 LINE 傳送」按鈕：按下顯示模擬完成提示（不真的產生檔案或傳送）。
- 產生紀錄列在該租客的文件歷史。

### 功能導覽（三條流程）
1. 新增上游租約 → 系統自動比對下游租約 → 出現風險警示 → 一鍵建立續租通知待辦。
2. 租客退租 → 押金結算單自動列出扣款項 → 確認 → 退款紀錄與證明歸檔 → 狀態變已退還。
3. 選租客 → 產生續約書 → 欄位自動帶入的預覽 → 以 LINE 傳送（模擬）。

## 驗收標準

- [ ] 上游租約列表可看、可搜尋、可篩「有風險」，至少 3 間顯示紅色風險警示且文字說得出兩個到期日
- [ ] 物件詳情頁看得到上下游兩份租約並列的時間軸
- [ ] 押金總覽有四種狀態，逾期未結算至少 1 筆並有提醒；結算流程可從頭點到「已退還」
- [ ] 文件中心 8 種文件都能選、選租客後預覽欄位自動帶入正確的假資料；「下載」「傳送」有模擬完成提示
- [ ] 功能導覽三條流程都能自動播放與手動切步，畫面狀態隨步驟改變
- [ ] 全部畫面在 iPhone 寬度可讀、無橫向捲動；`make check` 綠燈

## 邊界（明確不做什麼）

- 不真的產生 PDF、不真的傳 LINE。
- 不做租約編輯表單的完整驗證（示範用表單能送出、顯示結果即可）。
- 不做退租整備清單本身（屬 DEMO-04），本票只引用其扣款結果。
