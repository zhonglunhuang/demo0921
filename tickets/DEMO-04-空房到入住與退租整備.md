## 目的（要解決什麼問題）

空房是包租代管最大的損失來源。現有工具多半只管「已出租之後」；本票展示從租客通知不續租開始，
系統如何自動推進「即將空房 → 整備 → 招租 → 帶看 → 簽約 → 入住」整條漏斗，以及退租後必須走完的
復原整備流程，房間才重新回到可出租庫存（對應需求 #3、#5）。

> **共同背景（8 張票共用）**：本專案是「提案網站」，不是真正的營運系統。系統虛構品名「租務中樞」，
> 客戶化名「安居包租代管」。全站純靜態 HTML/CSS/JS、Apple 網站風格（白底為主、黑底區塊穿插、大字標題、
> 毛玻璃導覽列、滾動淡入）、繁體中文、手機可看。所有資料為假資料（同一批 103 間物件，桃園中壢為主），
> 定義在共用資料檔，各功能畫面互相一致。每個功能都要同時出現在兩條路徑：
> (A) **進系統操作**——可點、可切換、有假資料在跑的畫面；
> (B) **功能導覽**——一條步驟流程，畫面在頁上逐步動起來（可自動播放、可手動上下一步），旁邊有白話說明。

## 使用角色與情境

- 客戶以「租務管理員」視角操作漏斗看板與整備清單。
- 功能導覽展示兩條流程的動態。

## 需求細節

### #3 空房 → 招租 → 帶看 → 簽約 → 入住 漏斗
- 看板：欄位為「即將空房 / 整備中 / 招租中 / 帶看預約 / 已收訂 / 已簽約 / 已入住」，每欄有房間卡片，
  卡片可用按鈕推進到下一欄（不一定要拖曳）。
- 租客通知不續租 → 房間自動切「即將空房」→ 自動產生待辦：拍照、租金建議、刊登資料、清潔排程。
- 房間招租頁：租金建議（顯示同區同房型行情區間）、591 / 社群刊登文案一鍵產生（可複製）、詢問紀錄、
  帶看預約（簡易日曆，可新增預約）、訂金紀錄、簽約按鈕（帶到 DEMO-02 的文件產生）。
- 統計：平均空置天數（全部 / 各區）；**空置超過 7 天**的房間卡片顯示提醒「是否價格有問題？」並附租金建議；
  假資料至少 2 間空置超過 14 天。

### #5 退租復原／整備流程
- 退租整備清單（每間退租房一份）：電表拍照、鑰匙回收、家具設備檢查、牆面、床墊、冷氣、衛浴、清潔、垃圾、
  欠費結清、押金結算、是否需油漆 / 修繕、重新拍照、恢復招租。每項可勾選、可附照片（假圖）、可備註。
- 勾到「需油漆 / 修繕」→ 可一鍵建立工單（連到 DEMO-05）。
- 清單全部完成前，「可出租」按鈕不可按；按下後房間回到漏斗「招租中」並進入庫存。
- 進度顯示：已完成 X / 14 項，逾期未完成整備的房間在看板上標記。

### 功能導覽（兩條流程）
1. 租客在 LINE 說不續租 → 房間自動切即將空房 → 待辦自動產生 → 刊登文案產生 → 帶看預約 → 收訂 → 簽約 → 入住。
2. 退租整備清單逐項打勾 → 勾到需油漆 → 建立工單 → 完工 → 全部完成 → 按「可出租」→ 房間回到招租中。

## 驗收標準

- [ ] 漏斗看板 7 欄都有卡片，卡片可推進到下一欄，畫面即時更新
- [ ] 至少 2 間空置超過 14 天並顯示「是否價格有問題」提醒與租金建議；平均空置天數有數字
- [ ] 招租頁可產生並複製刊登文案、可新增一筆帶看預約
- [ ] 退租整備清單 14 項可勾選，全部完成前「可出租」不可按，完成後房間回到招租中
- [ ] 兩條功能導覽可自動播放與手動切步
- [ ] iPhone 寬度可讀；`make check` 綠燈

## 邊界（明確不做什麼）

- 不真的刊登到 591 或社群、不串行情資料（行情區間為假資料）。
- 不做租客端的不續租操作介面（屬 DEMO-06 的 LINE 選單），本票只接收其結果。
