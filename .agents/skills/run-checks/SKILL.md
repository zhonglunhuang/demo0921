# 改完一定要跑的檢查

任何改動完成後，**至少**跑對應的檢查，全綠才算完成。
本清單由 setup 初始化時填寫、之後由 framework 入口維護（技術棧變了要同步改這裡與 Makefile）。

## 票務與框架一致性（一律要跑）

```
make check          # 目前至少包含 ticket-lint；專案檢查指令設定後會一併跑
```

## 專案檢查指令

本專案是純靜態 HTML/CSS/JS，沒有建置與套件管理，檢查只有兩段：

```
make static-check   # 靜態站基本檢查（已包含在 make check 裡）
```

`static-check` 會檢查：

- `src/index.html` 存在。
- 所有 HTML 引用的站內檔案（連結、css、js、圖片）確實存在——路徑打錯會被抓出來。
- 沒有以 `/` 開頭的站內絕對路徑（GitHub Pages 子路徑下會失效）。
- 沒有殘留的 `TODO` / `Lorem ipsum` / `{{佔位}}` 內容被交出去給客戶看。

改了畫面時，**指令綠燈不等於做好**：一定要在瀏覽器實際開過該頁，並走 `user-walkthrough`
以真人視角把使用路徑點完。

## 多介面同步

若變更是使用者可見功能、API 契約、權限、狀態流程，且專案有多個介面（Web / Mobile / 桌面），
除非使用者明確限定只改單一介面，必須同時檢查並驗證所有介面已同步。

## 回報

- 把實際指令輸出講清楚；測試有失敗就貼出失敗內容，不要宣稱通過。
- 檢查不是綠燈就不算完成。
- 若只改單一介面，要說明是使用者明確限定，或其他介面無需同步的具體原因。
