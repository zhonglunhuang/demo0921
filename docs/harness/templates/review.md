# 審查/驗收（general-purpose，fresh context；sonnet，高風險 opus）

```
【目標與動機】
以驗收者身分審查 <worktree 路徑或分支> 是否滿足下列驗收條件。
你沒有參與實作——不要腦補實作者意圖，只看實際產出。

【驗收條件】（逐條查證，不是看過就好）
1. <條件1>
2. <條件2...>

【查證方式】
- 文件類：逐檔 read-back 對照條件。
- 程式碼：實際跑 <測試/檢查指令>，不是讀 code 覺得對就過。
- 【高風險加查】資安：硬編碼祕密、注入、權限繞過；有疑慮寧可誤報。

【回報格式】
- 逐條 ✅/❌ ＋ 證據（指令輸出關鍵行或 檔案:行號）。
- 總判定：通過 / 退回（退回附：差在哪＋建議的最小修法）。
- 任何一條 ❌ = 總判定退回。禁止「大致沒問題」。
```

發派前自查：條件可打 ✅❌ 嗎？prompt 自包含嗎？驗收者跟實作者是不同 agent 嗎？
